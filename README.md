# Итоговая работа — ELT-пайплайн сети «Горизонт»



## Назначение



Проект реализует воспроизводимый ELT-пайплайн для розничной сети «Горизонт».



В проекте используются:



- PostgreSQL — аналитическая база данных;

- Apache Airflow — оркестрация загрузки данных;

- dbt — трансформации и проверки качества данных;

- Data Vault 2.0 — модель Core/DDS;

- Medallion Architecture — разделение на слои Staging, Core/DDS и Data Marts;

- DQ-тесты — контроль качества данных;

- SQL reconciliation — сверка исходных и агрегированных данных;

- Metabase — визуализация бизнес-показателей.



## Источники данных



В проекте представлены следующие источники:



- кассовые данные — CSV;

- данные программы лояльности — CSV;

- данные HR — JSON/API-источник.



Для формирования аналитических витрин также используются справочные данные товаров и магазинов.



## Архитектура



Основной поток обработки данных:



Источники → Staging → Data Vault 2.0 / Core → Data Marts → BI / DQ



### Staging



Первичная загрузка исходных данных с минимальными преобразованиями.



### Core / DDS



Хранение интегрированных данных в соответствии с подходом Data Vault 2.0:



- Hubs;

- Links;

- Satellites.



### Data Marts



Основные аналитические витрины:



- dim_calendar;

- dim_product;

- dim_store;

- fct_sales_daily.



## Структура проекта



- airflow/ — Airflow DAG и загрузчик;

- data/ — исходные и демонстрационные данные;

- dbt/horizon/ — dbt-модели, тесты и макросы;

- sql/ — SQL-скрипты и контрольные проверки;

- docs/ — архитектура, модель и документация;

- dashboard/ — спецификация BI-визуализаций;

- evidence/ — результаты проверок и скриншоты;

- docker-compose.yml — конфигурация Docker-окружения.



## Запуск проекта



### 1. Запуск Docker-окружения



docker compose up -d



### 2. Airflow



Airflow доступен по адресу:



http://localhost:8080



Основной DAG:



horizon_elt_daily



### 3. dbt



Для запуска dbt внутри контейнера Airflow:



cd /opt/airflow/dbt/horizon

dbt deps

dbt build



### 4. PostgreSQL



Параметры учебного окружения:



- Database: horizon

- User: horizon

- Port: 5432



## Контроль качества данных



В проекте реализованы проверки:



- not_null;

- unique;

- допустимых значений;

- отсутствия дублирующихся Hub-ключей;

- корректности суммы продажи;

- reconciliation исходных данных и витрицы;

- отсутствия дублей после повторного запуска.



## Reconciliation



Сверка выполняется между исходными кассовыми данными и витриной fct_sales_daily.



Контрольный показатель:



difference = total_raw - total_mart



Ожидаемый результат:



difference = 0



status = PASS



## Идемпотентность



Повторный запуск пайплайна не должен приводить к появлению дубликатов.



Контролируются:



- количество строк;

- сумма продаж;

- уникальность ключей;

- количество дублирующихся записей.
